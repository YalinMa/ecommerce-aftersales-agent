# V6 学习笔记：产品化

## 这一版做了什么

到 V5 为止，网页是一个"开发者调试页"：左边聊天、右边看工具调用。V6 把它变成真实用户、真实客服都能用的产品形态：

| 页面 | 谁在用 | 做什么 |
|---|---|---|
| `/shop` 商城前台 | 用户 | 看订单；右下角在线客服；每个订单的「联系客服」会带上订单号 |
| `/console` 人工坐席工作台 | 人工客服 | 转人工的会话排队、接入、回复、交还 AI；顶部是当天运营数据 |
| `/debug` 开发者视图 | 开发者 | 原来的调试页：工具调用、耗时、核查结果 |
| `/eval` 评测报告 | 开发者 | V5 的评测报告 |

![商城前台：AI 查完物流后转人工](images/shop-handoff.jpg)

## 一次完整的转人工流程

```
用户在商城说"空气炸锅这么久没到，我要投诉"
  │
  ├─ AI：查订单 → 查物流 → 安抚 → 调用 transfer_to_human（交接摘要：订单号、物流停滞 108 小时、用户诉求）
  │
  ├─ 会话状态 ai → queued，进入人工队列
  │    用户：窗口显示"正在为您转接人工客服，前面还有 0 位"，之后每 2 秒拉取新消息
  │    用户继续发消息：不再交给 AI，直接存给人工坐席
  │
  ├─ 坐席在工作台看到排队会话：AI 交接摘要、完整对话、哪条回复被用户点了 👎
  │    接入并回复 → 状态 human，用户窗口变成蓝色"人工客服 · 小周"，实时收到回复
  │
  └─ 坐席点「交还 AI」→ 状态 ai
       人工说过的话作为上下文交给 AI，用户再问"刚才人工说顺丰会打电话，是今天吗？"
       AI 回答"人工客服小周已经为您提交了物流加急核查，顺丰会在今天内给您回电"
```

![人工坐席工作台](images/console.jpg)

## 设计要点

**1. 转人工后 AI 不再回复。** 会话进入 `queued` / `human` 状态后，用户的消息直接存进客服平台数据库给坐席看，不再请求大模型。否则就会出现 AI 和人工同时回复、说法互相矛盾的情况。

**2. 交还 AI 时不能"失忆"。** 人工坐席的回复不在 AI 的对话历史里（历史只有 user / assistant / tool 三种角色，人工的话没地方放）。交还时把人工说过的话整理成一段系统提示，附在用户的下一条消息后面，并要求"不要与人工客服的答复矛盾"。

![交还 AI 后，AI 知道人工说过什么](images/shop-human-to-ai.jpg)

**3. 客服平台有自己的数据库。** `data/service.db` 存会话、消息、转人工记录、用户反馈，和商城的 `mall.db` 分开。这延续了 V4 的边界：商城管订单和售后，客服平台管"谁什么时候聊了什么、满不满意"。

**4. 用户侧不展示技术细节。** 开发者视图显示工具名（`get_logistics`），用户侧显示"正在查询物流…"。核查未通过、耗时等信息只给坐席和开发者看。

**5. 坐席工作台不打断输入。** 工作台每 3 秒刷新，但会话详情只在有新消息或状态变化时才重绘，并保留坐席正在输入的草稿。

## 用户反馈和运营数据

每条 AI 回复下面有 👍 / 👎。这把 V5 的评测从"测试场景"延伸到了"真实对话"：

- 坐席工作台里，被点了 👎 的回复会标红，方便人工复核。
- 被点 👎 的对话是最好的新测试场景来源：把它加进 `scenarios/`，修好之后它就成了回归测试的一部分。

工作台顶部的运营数据（来自 `service.db` 和每条 AI 回复记录的耗时）：

| 指标 | 含义 |
|---|---|
| 今日商城会话 | 商城前台发起的会话数 |
| 转人工率 | 转人工的会话占比。太高说明 AI 解决不了问题，太低要检查是否漏转 |
| 其中规则兜底 | 由 V3 的关键词规则强制转接的次数。数量上升说明模型越来越不愿意主动转 |
| 当前排队 | 等待坐席接入的会话数 |
| 👍 / 👎 | 用户反馈 |
| AI 平均首字 | 用户发出消息到看到第一个字的平均时间 |

## 没有做的

- **长对话的上下文压缩。** 测试对话都在 10 轮以内，没有触及上下文上限。真实场景需要在对话变长时把早期轮次压缩成摘要，同时保证工具调用和结果成对保留。
- **会话恢复。** AI 的对话历史在服务进程内存里，重启后丢失（客服平台数据库里的消息记录还在）。生产环境需要把对话历史也持久化。
- **真实的消息推送。** 用户侧用 2 秒轮询拉取人工回复，简单可靠；规模大了应改为 WebSocket 或 SSE 长连接。
- **坐席分配和多坐席并发。** 目前任何坐席都能接入任何会话，没有按技能、负载分配。
