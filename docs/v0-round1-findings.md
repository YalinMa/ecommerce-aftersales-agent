# V0 第一轮回放：DeepSeek vs OpenAI vs 通义千问

- 日期：2026-10-11
- 数据：`runs/20261011-162101/`，14 个场景，同一份 system prompt，各模型均用默认参数
- 模型：deepseek-flash、gpt-5.5（reasoning_effort=low）、qwen-plus

## 总览

| | DeepSeek | OpenAI | 通义千问 |
|---|---|---|---|
| 平均每场景耗时 | **3.2s** | 6.4s | 6.9s |
| 输入 / 输出 tokens | 30.8k / 4.9k | 35.3k / **2.9k** | 33.3k / 3.5k |
| ✅ 完全达标 | **11** | **11** | 1 |
| ⚠️ 有瑕疵 | 3 | 3 | 4 |
| ❌ 不达标 | **0** | **0** | 9 |
| 编造政策外内容 | 1 处轻微 | **0** | 9 处 |
| 误用 `[转人工]` | 0 | 0 | 5 轮 |
| 风格 | 口语、亲切，略啰嗦 | 简洁克制，偏书面 | emoji、加粗、长列表 |

评判口径：
- ❌ 判断错误、编造政策外内容，或者在不该转人工时带了 `[转人工]`（程序会照此真的转人工）。
- ⚠️ 结论正确，但有违反对话规范之处，比如一次问超过两个问题、重复追问、回答含糊，或补充了政策外的小细节。

## 各模型画像

**DeepSeek（deepseek-flash）**：速度最快，是另外两家的一半左右；语气最像真人客服，共情做得好。缺点是话偏多（输出 token 最高），偶尔补充政策没写的小细节。

**OpenAI（gpt-5.5）**：最守规矩，14 个场景零编造，输出最精简。缺点是偏保守、偏书面：`price-01` 用户已经说了是直播间，它仍然回答"如果是直播间专属价就不在范围内"，把判断推回给用户；`quality-02` 漏掉了关键政策点。

**通义千问（qwen-plus）**：问题集中在"太想帮忙"——主动补充政策没有的处理方式、主动提供自己没有的能力，于是越过了政策和能力边界。另外不遵守格式要求，还在 5 轮对话里误用了转人工标记。

## 三家共同的问题

`vague-01` 第 1 轮三家都一次问了 3 个问题（商品、问题、签收时间），违反了"一次最多问两个问题"。说明这条规则写得不够有约束力，或者模型认为这 3 个信息缺一不可。可以考虑删掉这条规则，或者明确优先问哪两个。

## 结论

1. **同一份 prompt，模型差异比预想的大。** DeepSeek 和 OpenAI 在 V0 基本达标，通义需要专门调 prompt。
2. **选型要看场景取舍：** 追求体验和成本，选 DeepSeek；追求合规、零编造，选 OpenAI。
3. **`[转人工]` 这种靠模型自觉输出的文本标记不可靠。** V1 改成工具调用（`transfer_to_human`），由程序判断是否转接。
4. **人工逐条检查 14 × 3 段对话已经很费时间。** 这正是 V5 要做自动评测的动机。
